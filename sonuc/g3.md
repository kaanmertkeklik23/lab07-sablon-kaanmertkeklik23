# Görev 3 — Yüzleştirme: SQL vs Doküman

## PostgreSQL (JOIN + GROUP BY) Sorgusu ve Sonucu

```sql
SELECT d.ders_id, d.ad, COUNT(k.kayit_id) AS adet
FROM dersler d
JOIN kayitlar k ON d.ders_id = k.ders_id
GROUP BY d.ders_id, d.ad
ORDER BY adet DESC
LIMIT 5;
```

Çıktı:
```text
 ders_id |             ad              | adet 
---------+-----------------------------+------
       6 | İleri Pilates — Başlangıç   |   18
       1 | Kardiyo Dayanıklılık — İleri|   16
      18 | Gençlik Yüzme — Başlangıç   |   16
       5 | Hamile Yogası — Orta        |   15
      23 | Fonksiyonel Antrenman — İleri|  15
(5 rows)
```
En çok kayıt alan dersin kayıt sayısı: 18 (`ders_id = 6`).

## MongoDB (Aggregate + $group) Boru Hattı ve Sonucu

```javascript
db.kayitlar.aggregate([
  { $group: { _id: "$ders_id", adet: { $sum: 1 } } },
  { $sort: { adet: -1 } },
  { $limit: 5 }
])
```

Çıktı:
```javascript
[
  { _id: 6, adet: 18 },
  { _id: 1, adet: 16 },
  { _id: 18, adet: 16 },
  { _id: 5, adet: 15 },
  { _id: 23, adet: 15 }
]
```
En çok kayıt alan dersin kayıt sayısı: 18 (`_id: 6`). İki tarafta da sayı birebir aynı çıktı.

## Değerlendirme

Açıkçası önceki haftalardan elimiz alıştığı için gruplama sorgusunu SQL tarafında `JOIN` ve `GROUP BY` ile yazmak bana daha doğal ve okunaklı geldi; MongoDB'deki `aggregate` boru hattında süslü parantez ve aşama sırasını (`$group` -> `$sort` -> `$limit`) takip etmek biraz daha dikkat istiyor. Uygulamada bir ders kartı ekranını (ders + eğitmen + salon bilgisi bir arada) çekerken MongoDB modeli eğitmen ve salonu ders dokümanının içine gömdüğü için hiçbir JOIN işlemine gerek kalmadan tek okumada (`findOne`) bütün veriyi getiriyor. Ancak bir eğitmenin adı veya branşı değişirse ilişkisel modelde sadece `egitmenler` tablosundaki tek bir satırı güncellemek yeterliyken, MongoDB tarafında o eğitmenin geçtiği bütün ders dokümanlarını tek tek bulup güncellemek gerekeceği için doküman modeli güncelleme anomalisi açısından acı çeker. Bu yüzden FıratFit'te ders kataloğu ve üye profili/telefonları gibi sık birlikte okunan veriler için MongoDB'yi, kredi bakiyesi, ödemeler ve yabancı anahtar bütünlüğü gerektiren ders kayıtları için ise PostgreSQL'i seçerdim.
